## 📌 预览
形式化定义 MAS 的通信过程和 G-Memory 三层图结构的数学表达。

---

In this section, we establish the notation and formalize key concepts of multi-agent systems and G-Memory's hierarchical memory architecture.

**Multi-agent System Formalization.** Consider a multi-agent framework represented by a directed graph $\bar{\mathcal{G}} = (\mathcal{V}, \bar{\mathcal{E}})$, where $|\mathcal{V}| = N$ is the number of agents and $\mathcal{E} \subseteq \mathcal{V} \times \mathcal{V}$ defines their communication channels. Each node $C_i \in \mathcal{V}$ corresponds to an individual agent described by the quadruple:

$$C_i = (\text{Base}_i, \text{Role}_i, \text{Mem}_i, \text{Plugin}_i),$$

where $\text{Base}_i$ denotes the underlying large language model instance, $\text{Role}_i$ specifies the agent's designated role or persona, $\text{Mem}_i$ encapsulates its memory state, including past interactions or external knowledge stores, and $\text{Plugin}_i$ is the set of auxiliary tools (e.g., web-search engine).

> 💡 **Agent 四元组**: 每个 agent 由 LLM + 角色 + 记忆 + 工具 组成。G-Memory 主要操作的是 Mem_i 这个维度——为每个 agent 注入 role-specific 的记忆内容。

Upon receiving a user query $Q$, the system evolves through $T$ synchronous communication epochs. At each epoch $t$, we derive a topological ordering $\pi = [\pi_1, \ldots, \pi_N]$ of the nodes such that if there is an edge from $\pi_j$ to $\pi_k$, then $j < k$, which guarantees that every agent processes its inputs only after all its predecessors have acted. For each agent $C_i$ in $\pi$, its output at iteration $t$ is computed as:

$$r_i^{(t)} = C_i\Big(P_{\text{sys}}^{(t)}, Q, \{r_j^{(t)} : C_j \in \mathcal{N}^-(C_i)\}\Big),$$

where: $r_i^{(t)}$ denotes the response generated by $C_i$ (which may include reasoning steps, intermediate analyses, or final proposals), $P_{\text{sys}}^{(t)}$ comprises global instructions (including each agent's $\mathcal{R}_i$), $\mathcal{N}^-(C_i)$ is the set of in-neighbors of $C_i$, whose outputs serve as contextual inputs. After all agents have acted, a global aggregation operator $\mathcal{A}$ fuses the collection of responses into an interim solution $a^{(t)}$:

$$a^{(t)} = \mathcal{A}(r_1^{(t)}, \ldots, r_N^{(t)}).$$

Common implementations for $\mathcal{A}$ include majority voting schemes [48], hierarchical summarization via dedicated aggregator agents [13, 30], or simply adopting the final agent's output as the answer [47]. These epochs iterate for $t = \{1, \ldots, T\}$ until either a preset limit is reached or an early-stopping criterion is met [72], producing the final response $a^{(T)}$ to the query $Q$.

> 💡 **MAS 通信过程**: 
> 1. 按拓扑排序确定 agent 执行顺序（DAG）
> 2. 每个 agent 接收前驱 agent 的输出作为输入
> 3. 所有 agent 执行完后聚合结果
> 4. 多轮迭代直到收敛或达到上限
>
> 这个过程产生大量 utterance，正是 G-Memory 要管理的对象。

**Memory Architecture.** Our proposed G-Memory orchestrates and manages the memory of multi-agent systems via the following three hierarchical graph structures:

**[★] Interaction Graph (Utterance Graph).** For query $Q$, let $\mathcal{G}_{\text{inter}}^{(Q)} = (\mathcal{U}^{(Q)}, \mathcal{E}_u^{(Q)})$ denote its interaction trajectory, where (i) nodes represent atomic utterances, with each $(A_i, m_i)$ containing $A_i \in \mathcal{V}$ (speaking agent), and $m_i$ (textual content), (ii) Edges $\mathcal{E}_u^{(Q)} \subseteq \mathcal{U}^{(Q)} \times \mathcal{U}^{(Q)}$ follow temporal relationships: $(u_j, u_k) \in \mathcal{E}_u^{(Q)} \iff u_j$ is transmitted to and inspires $u_k$.

> 💡 **Interaction Graph 详解**: 
> - 节点 = 单条 utterance（谁说的 + 说了什么）
> - 边 = 时序/因果关系（utterance A 被传给了 utterance B 的作者，且影响了 B 的生成）
> - 本质是一个**加权有向的对话流图**，比简单的线性对话历史更能表达并行和交叉的信息流

**[★] Query Graph.** The query graph, storing previously tackled queries and metadata, is as follows:

$$\mathcal{G}_{\text{query}} = (\mathcal{Q}, \mathcal{E}_q) = \left(\left\{Q_i, \Psi_i, \mathcal{G}_{\text{inter}}^{(Q_i)}\right\}_{i=1}^{|\mathcal{Q}|}, \mathcal{E}_q\right),$$

where each node $q_i \triangleq (Q_i, \Psi_i, \mathcal{G}_{\text{inter}}^{(Q_i)})$ is composed of the original query $Q_i$, task status $\Psi_i \in \{\text{Failed}, \text{Resolved}\}$, and its associated interaction graph. The edges $\mathcal{E}_q \subseteq \mathcal{Q} \times \mathcal{Q}$ encode retrieval-based similarity between queries, with its meticulous topology.

> 💡 **Query Graph 详解**:
> - 节点 = 一个完整任务（query 文本 + 成功/失败状态 + 对应的 interaction graph）
> - 边 = 任务间的相似性/关联性（embedding 相似度建边）
> - 作用：当新 query 来时，找到相似的历史任务，然后通过边扩展到更多相关任务
> - 保留了成功/失败标记，便于后续区分学习

**[★] Insight Graph.** The highest-level insight graph is featured as follows:

$$\mathcal{G}_{\text{insight}} = (\mathcal{Z}, \mathcal{E}_i) = \Big(\underbrace{\langle\kappa_k, \Omega_k\rangle}_{\iota_k}{}_{k=1}^{|\mathcal{Z}|}, \mathcal{E}_i\Big),$$

where the node set $\mathcal{T} = \{\iota_k\}$ represents distilled insights, each node $\iota_k$ is composed of the insight content $\kappa_k$ and the set of supporting queries $\Omega_k \subseteq \mathcal{Q}$. The edges $\mathcal{E}_i \subseteq \mathcal{T} \times \mathcal{T} \times \mathcal{Q}$ forming hyper-connections where $(\iota_m, \iota_n, q_j)$ indicates insight $\iota_m$ contextualizes $\iota_n$ through query $q_j$.

> 💡 **Insight Graph 详解**:
> - 节点 = 一条洞察（策略文本 + 支持该洞察的 query 集合）
> - 边 = **三元超连接** $(\iota_m, \iota_n, q_j)$，表示洞察 m 通过 query j 的经验支撑了洞察 n
> - 这是最抽象的层级，存储的是可迁移的策略知识
> - 例如："在 clean 类任务中，必须先清洗物品再放置"这种跨任务的经验法则
>
> 💡 **三层图的层次关系**:
> ```
> Insight Graph (抽象策略)
>     ↑ Ω_k: 哪些 query 支持这个 insight
> Query Graph (任务索引)
>     ↓ G_inter: 每个 query 对应的对话记录
> Interaction Graph (原始轨迹)
> ```
> 这种层次化设计类似数据库的索引结构：insight 是高层索引，query 是中层，interaction 是原始数据。

## 🔖 Section 总结

### 关键数字速查
| 符号 | 含义 |
|------|------|
| $N$ | Agent 数量 |
| $T$ | 通信轮数 |
| $\mathcal{G}_{\text{inter}}$ | Interaction graph（utterance 级别） |
| $\mathcal{G}_{\text{query}}$ | Query graph（任务级别） |
| $\mathcal{G}_{\text{insight}}$ | Insight graph（策略级别） |

### 核心洞察
1. 三层图形成**从具体到抽象**的层次结构，每一层都有明确的节点/边语义
2. Insight graph 的超连接设计（三元组边）是一个精巧的设计——洞察之间的关联是通过具体 query 建立的
3. 这套形式化框架足够通用，可以适配不同的 MAS 通信拓扑
