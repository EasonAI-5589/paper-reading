# 3 Operations on Web3

## 📌 预览
系统化分类链上信息查询（3 层）和链上操作（3 类），为 Web3Agent 的任务空间建立形式化框架。

---

## 3.1 链上信息查询（On-chain Information）

分为三层结构，对应 Figure 3：

### System Layer（系统层）
- **支持的区块链网络**: 跨链互操作信息
- **预交易信息**: Gas 费、Nonce、Gas Limit 等交易前必要数据

### EOA Layer（外部账户层）
- **资产持有**: ETH/BNB 原生代币 + ERC-20 + NFT (ERC-721, ERC-1155) 余额
- **交易历史**: 所有交易记录，包含合约交互和 Token 转账
- **授权与权限**: 检查用户对合约的 Token 转移授权（allowance）

### SC Layer（智能合约层）
- **合约与 Token 信息**: 名称、符号、精度、总供应量等元数据
- **市场与价格数据**: 实时价格、流动性池深度、Swap 汇率、Oracle 价格
- **合约交互记录**: 历史函数调用、事件日志、Staking 池活动

> 💡 **批读**: 三层分类很好地覆盖了 DeFi 操作所需的信息范围。实际操作中，一个 Token Swap 需要同时查询三层信息：System（Gas）→ EOA（余额 + 授权）→ SC（合约验证 + 价格），体现了多步操作的复杂性。

## 3.2 链上操作（On-chain Operations）

三类核心操作，共 5 个操作入口：

| 操作类型 | 说明 | 前置检查 |
|---------|------|---------|
| **EOA → EOA 转账** | 用户间直接转账 | 余额检查 → Gas 估算 → Nonce 验证 |
| **EOA ↔ SC 同链交互** | Token Swap、Staking、赎回等 DeFi 操作 | 合约验证 → 授权检查 → 参数验证 → Gas 估算 |
| **跨链操作** | 通过跨链桥在不同链间转移资产 | 双链验证 → 桥合约交互 → 双重 Gas 估算 |

> 💡 **批读**: 跨链操作是最复杂的场景，涉及两条链的状态管理和多个智能合约交互。论文提到这部分支持，但实验中似乎主要聚焦于同链操作。

---

## 🔖 Section 总结

### 核心洞察
1. Web3 操作的复杂度来源于 **多层信息依赖** — 一个简单的 Swap 可能需要 5-8 步 API 调用
2. 操作前的 **安全检查链** 是关键：余额 → 授权 → 合约验证 → Gas 估算
3. 这个分类体系直接指导了后续 Instruction Chains 和 RAG chunk 的设计
