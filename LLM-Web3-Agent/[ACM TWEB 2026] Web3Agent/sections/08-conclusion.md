# 8 Future Vision & Limitations + 9 Conclusion

## 📌 预览
坦诚讨论系统局限性，包括可扩展性、安全性、比较评估缺失，以及未来研究方向。

---

## 8.1 可扩展性与泛化

**挑战**:
- 长依赖链 / 并发请求 → 上下文长度、延迟、API 吞吐量压力
- Chunk-based 检索隐含假设任务遵循可识别模式 → 面对未见过的 dApp 结构、非标准钱包流程时泛化能力有限

**潜在方向**:
- 多 Agent 范式: 专门化角色（风险评估、桥接选择、链感知规划）
- Schema 抽象 + 自描述 API 适配器: 自动对齐新合约接口和跨链协议

## 8.2 安全性与 Human-in-the-loop

- LLM 错误、对抗输入、协议变更 → 不可完全消除
- **Human-in-the-loop 是最可靠的最终验证屏障**
- 未来方向: 用户信任形成与调整研究、纵向部署观察、反馈粒度实验

## 8.3 比较评估缺失（重要局限）

作者承认：
- **未做系统性端到端对比**（vs 通用 LLM pipeline、Web3.py 规则脚本、其他 LLM-agent 工具包）
- 原因: 缺乏统一 benchmark、跨系统条件难以一致复制
- 未来: 需要统一评估 harness（标准化任务集、共享接口、确定性 replay）

> 💡 **批读**: 这是论文最大的软肋。只做了内部消融，没有与任何外部 baseline 做对比。虽然理由成立（缺乏标准 benchmark），但至少可以和 Web3.py 脚本做功能覆盖对比，或与 ChatGPT + 手动操作做效率对比。

## 9 Conclusion

Web3Agent 是一个可行性导向（feasibility-oriented）的系统，探索 LLM Agent 与 Web3 基础设施的集成：
- 端到端自然语言 → 链上执行
- 模块化架构支持多步推理和错误恢复
- 在模拟环境中验证了可行性

---

## 🔖 Section 总结

### 核心洞察
1. **可扩展性** 是从原型到生产的最大挑战 — 上下文窗口和 API 吞吐量是瓶颈
2. **泛化能力** 受限于 chunk store 的覆盖范围 — 本质上是一个知识工程问题
3. **比较评估缺失** 是论文最大不足，但也反映了 Web3 Agent 领域缺乏标准 benchmark
4. 作者正确地将系统定位为 "feasibility-oriented" — 这是概念验证，不是生产系统
