# 1. Introduction

## 核心动机

MLLMs（如LLaVA、Qwen-VL、GPT-4o）在视觉-语言联合感知、对齐和推理方面取得了显著进展。但面临两大效率瓶颈：

1. **高分辨率图像和长视频** → 视觉token数量可达数千甚至数万
2. **多轮对话和Chain-of-Thought推理** → 进一步延长历史上下文

由于Transformer的**二次复杂度**（$O(n^2)$），这导致：
- 显存消耗剧增
- 推理延迟增大
- 部署成本过高

## Token压缩的定义

> Token压缩 = 在保留关键跨模态语义的前提下，减少MLLM处理的token数量

**压缩目标的三种冗余来源**：
- **空间冗余 (Intra-Visual)**: 重复背景区域、相似patch
- **时序冗余 (Temporal)**: 视频相邻帧的高相似度
- **模态对齐冗余 (Cross-Modal)**: 与文本query无关的视觉token

## 本survey的三个核心问题

| 问题 | 关注点 |
|------|--------|
| **Where** | 压缩应该在MLLM架构的哪个模块进行？ |
| **Which** | 哪种压缩机制最适合特定部署场景？ |
| **What** | 剩余的开放挑战和未来方向是什么？ |

## 主要贡献

1. **分类体系**: 按MLLM架构位置（Vision Encoder / Projector / LLM）分类
2. **方法论分析与选择路线图**: 剖析关键设计维度，提供选择指南
3. **开放挑战与未来方向**: 理论基础、自适应性、评估体系等
