# 1. Introduction

## 1.1 MLLMs的能力与效率瓶颈

MLLMs（如LLaVA、Qwen-VL、GPT-4o、InternVL）在视觉-语言联合感知、跨模态对齐和复杂推理方面取得了显著进展，已成为通用多模态智能的核心载体。然而，随着应用场景从简单的图像描述扩展到高分辨率文档理解、长视频分析和多轮对话推理，效率瓶颈日益突出：

- **高分辨率图像**：单张图像经patch化后可产生数千个视觉token（如576→2880甚至更多）
- **长视频输入**：数十秒至数分钟的视频帧序列可产生数万个视觉token
- **多轮对话与Chain-of-Thought推理**：历史上下文持续增长，进一步放大序列长度

由于Transformer的**自注意力机制具有二次复杂度**（$O(n^2)$），这些场景导致：
- 显存消耗剧增（GPU memory瓶颈）
- 推理延迟大幅增大（latency不可接受）
- 部署成本过高（无法在端侧或资源受限环境运行）

> **[感受]** 效率问题的本质不只是"token太多"，而是视觉信息的密度与语言信息的密度存在根本性不对称。一张图像被切成576个patch token，但其中真正与用户query相关的语义可能只需要几十个token就能表达。这种信息密度的模态间失衡，才是token压缩研究的根本动机。论文将效率瓶颈归结于 $O(n^2)$ 的注意力复杂度，这固然是理论上的主导项，但在实际部署中，**内存带宽(memory bandwidth)** 和 **KV-cache的显存占用**往往比纯计算量更先成为瓶颈——减少token数不仅降低了FLOPs，还直接减小了KV-cache的大小和每步解码时的内存访问量。从MLLM效率优化的角度看，仅靠硬件升级或算子优化无法解决这个根源性问题——我们需要在算法层面重新思考"视觉信息应该以多大的粒度进入语言模型"。此外值得注意的是，压缩的紧迫性随着MLLM应用场景的扩展（从静态图片→动态视频→交互式agent）只会越来越强。

## 1.2 Token压缩的定义与冗余分类

**核心定义**：

> Token压缩 = 在保留关键跨模态语义的前提下，减少MLLM处理的token数量

论文将视觉token中的冗余归纳为**三种来源**：

| 冗余类型 | 具体表现 | 典型场景 |
|---------|---------|---------|
| **空间冗余 (Spatial/Intra-Visual)** | 重复的背景区域、相邻patch的高度相似性 | 高分辨率图像中大面积均匀区域 |
| **时序冗余 (Temporal)** | 视频相邻帧之间的高重叠度 | 视频中静止或缓慢变化的片段 |
| **跨模态对齐冗余 (Cross-Modal)** | 与文本query语义无关的视觉token | "图片中的猫是什么颜色"——背景建筑物token无关 |

> **[感受]** 三类冗余的划分虽然直观，但在实际方法设计中并不正交。视频中相邻帧的冗余既是时序冗余也是空间冗余的一种表现；而cross-modal冗余的判定本身依赖于文本query，是一种动态的、task-dependent的概念。更深层的问题在于，"关键跨模态语义"缺乏形式化定义——不同任务对"关键"的理解差异巨大（OCR需要几乎所有像素级细节，粗粒度VQA仅需高层语义），这一模糊性贯穿整篇survey，也是该领域缺乏统一理论框架的根源。从效率优化的角度看，理想的压缩应该是**内容自适应+任务自适应**的，但目前大多数方法仍是固定策略。未来可能需要一种统一的信息论框架来定义"视觉token对于给定query的信息量"，从而为压缩率的选择提供理论依据，而不是依靠启发式规则或经验调参。

## 1.3 三个核心问题

论文以三个递进的问题组织全文：

| 问题 | 关注点 | 对应章节 |
|------|--------|---------|
| **Where（在哪压缩）** | 压缩应该在MLLM架构的哪个模块（Vision Encoder / Projector / LLM内部）进行？不同位置有何trade-off？ | §3–§5 |
| **Which（怎么选）** | 哪种压缩机制最适合特定部署场景？不同冗余类型适合什么方法？ | §6 |
| **What（还有什么）** | 当前方法的局限性、剩余的开放挑战和未来方向 | §7 |

> **[感受]** "Where / Which / What"的组织方式对做效率优化的人非常友好：先回答"在哪里动刀"，再回答"用什么刀"，最后讨论"还有什么没解决"。这种按架构位置→机制选择→开放问题的层次结构，比按时间线或按方法类型的survey组织方式更具工程指导意义。在实际做MLLM效率优化研究时，"Where"是第一个需要回答的设计决策——它决定了你能获取什么信息（encoder内部有attention map，projector处有跨模态信号，LLM内部有text-visual交互信号）。"Which"的回答则需要结合具体的部署约束（是要training-free的即插即用？还是允许端到端微调？是追求极致压缩率还是在精度损失为零的前提下适度压缩？）。遗憾的是，现有工作很少在统一的实验设置下对这三个维度做系统对比，导致不同方法之间的可比性较差。这也正是本survey的"选择路线图"试图弥补的空白。

## 1.4 主要贡献

论文自述三大贡献：

1. **系统分类体系 (Taxonomy)**：按MLLM架构位置（Vision Encoder内部 / Vision Encoder-Projector之间 / Projector内部 / LLM内部）建立分类，将token压缩方法映射到具体的架构组件上
2. **方法论分析与设计路线图 (Methodological Analysis + Roadmap)**：剖析关键设计维度（压缩策略、信息保留机制、训练需求等），提供面向不同场景的方法选择指南
3. **开放挑战与未来方向 (Open Challenges + Future Directions)**：涵盖理论基础缺失、自适应压缩、评估体系不完善、多模块协同等关键问题

> **[感受]** "按架构位置分类"是本文最大的结构性贡献，因为它直接对应了工程实现中的设计决策。相比按"方法类型"（pruning/merging/pooling）分类，按架构位置分类更容易帮助研究者定位自己的工作在整个pipeline中的角色，也更容易发现不同位置方法的互补性和可组合性。贡献2（选择路线图）是最有实用价值的部分——面对50+方法，实践者最需要的就是一棵决策树而非方法罗列。不过论文的路线图仍偏定性描述，缺少量化的选择依据（如"在X场景下，方法A比B快Y%且精度仅降Z%"）。此外，这种分类也有局限：一些方法是跨模块的（如端到端学习的方法可能同时影响projector和LLM的行为），难以严格归入单一位置。

## 1.6 发展时间线

论文Figure 1给出了详细的发展时间线，关键节点如下：

- **2022年**：奠基性工作
  - **ToMe** (Token Merging)：在ViT中通过二分匹配合并相似token，开创了visual token merging范式
  - **BLIP-2**：通过Q-Former实现跨模态token压缩，将数百个视觉token压缩为固定数量的query token
- **2023年**：早期探索
  - **MovieChat**：面向长视频理解的token memory机制
  - **Honeybee**：探索更高效的视觉-语言projector设计
  - **LLaVA-STF** 等方法开始出现
- **2024年**：爆发式增长（30+方法）
  - **FastV**：基于attention score的LLM内部token pruning，training-free
  - **PyramidDrop**：分层渐进式token丢弃
  - **VisionZip**：基于信息论的视觉token压缩
  - 以及大量其他方法在encoder/projector/LLM各个位置展开探索
- **2025年**：持续快速发展（20+方法），趋势特征：
  - **多模块协同压缩**：不再局限于单一位置，开始探索跨模块的联合优化
  - **极端视频压缩**：面向超长视频（小时级别）的高压缩比方法
  - **自适应压缩**：根据输入内容和query动态调整压缩率

> **[感受]** 2024年单年涌现30+方法，说明这是一个极度活跃的竞争领域。但这也意味着很多方法可能缺乏充分验证就已发表，方法间的公平对比尤为困难。从时间线可以清晰看到演化逻辑：2022年的工作（ToMe、BLIP-2）本质上是从CV领域和预训练范式中借鉴的思路；2023年开始有人意识到MLLM场景的特殊性；2024年的爆发则是因为LLaVA等开源MLLM的普及降低了实验门槛，加上高分辨率和视频理解的需求激增。值得关注的是2025年"多模块协同"的趋势——这意味着单点压缩的收益可能已经接近天花板，未来的增益需要来自pipeline级别的全局优化。这个演进路径与MLLM本身的发展高度同步——随着模型能力和应用场景的扩展，压缩方法也在从"能用"走向"好用"。从研究选题的角度看，如果还停留在"在某个单一位置做一个新的pruning/merging方法"，可能已经难以产生足够的增量贡献。更有价值的方向可能是：(1) 建立压缩方法的理论分析框架；(2) 设计能感知下游任务的自适应压缩策略；(3) 探索压缩与其他效率优化技术（量化、蒸馏、稀疏注意力）的协同效应。
