# 4. Problems of Current Framework

## 4.1 Loose Matching

### 原文

The current evaluation framework determines the correspondence between g and p only with the IoU threshold τ. Thus, it causes **loose matching**: a generated caption is matched with many reference captions or a reference caption is matched with many generated captions.

The order of generated captions produced by the matching does not correspond to the order of reference captions, i.e., the loose matching disregards the story of the video.

**Example:** When reference and generated captions are given as shown in Figure 2, the current framework produces matches: $(g_1, p_1), (g_1, p_2), (g_2, p_1), (g_2, p_2), (g_3, p_1), (g_3, p_3), (g_4, p_3)$

The order of generated captions: $p_1, p_2, p_1, p_2, p_1, p_3, p_3$ — which is invalid because it contains many duplicates.

The best order should be: $p_2, p_1, p_3$

Furthermore, loose matching produces overestimations of METEOR scores:
- Same sentences with different length proposals can all match
- Multiple different sentences for a proposal can improve average score

---

### 理解与批注

#### Loose Matching 的问题

```
Reference:  g1 ── g2 ── g3 ── g4  (正确顺序)
            ↓    ↓    ↓    ↓
Current:    p1   p1   p1   p3
            p2   p2   p3   
                           
结果顺序: p1, p2, p1, p2, p1, p3, p3  ❌ 包含重复
正确顺序: p2, p1, p3  ✅
```

> 💡 Current 评测完全**忽略了故事顺序**

#### 冗余 Caption 问题

**场景 1: 相同句子 + 不同 proposal**
```
p1: "A man walks" [0-10s]  IoU(g1)=0.9
p2: "A man walks" [5-15s]  IoU(g1)=0.4
p3: "A man walks" [3-12s]  IoU(g1)=0.6

τ=0.9: 只匹配 p1
τ=0.5: 匹配 p1, p3 → 分数更高？！
```

**场景 2: 多个不同句子**
```
p1: "A man walks"      METEOR(g1)=0.0
p2: "Someone walking"  METEOR(g1)=0.3
p3: "A person walks"   METEOR(g1)=0.6

只有 p1: 平均=0.0
三个都有: 平均=0.3 → 更高！
```

> ⚠️ 生成更多（冗余）caption 反而得分更高

## 4.2 Averaging METEOR Scores

### 原文

As shown in Equation (3), the sum of METEOR scores is averaged based on the number of matched pairs. The number of captions generated by a system, |P|, and the number of reference captions, |G|, are disregarded in calculating the metric.

Thus, it cannot take into account:
- **Coverage** of generated captions (recall)
- **Accuracy** of the captions (precision)

Most current DVC systems generate several hundred caption sentences for a video. The average number is around several hundred, while reference is only 3-4. This is a **critical problem** since humans cannot read several hundred sentences.

Furthermore, too few captions are also inappropriate because they cannot represent the whole story. To penalize inappropriate captions, we can try replacing the denominator with |P| or |G|, but this causes scores to potentially exceed 1.0.

---

### 理解与批注

#### 为什么分数不变？

Current 评测公式：
$$\text{Score} = \frac{\sum \text{METEOR}}{|\text{匹配对数}|}$$

| 生成数量 | 匹配对数 | 分数 |
|---------|---------|------|
| 3 | ~10 | ~0.5 |
| 100 | ~300 | ~0.5 |
| 300 | ~900 | ~0.5 |

> 💡 分子分母同比例增长，分数几乎不变！

#### 真实数据

| 系统 | 生成 caption 数 | Reference |
|------|----------------|-----------|
| E2E Transformer | 228 | 3-4 |
| LSTM | 97 | 3-4 |

> ⚠️ 生成数量是参考的 **25-60 倍**，但分数差不多

#### 为什么不能简单修复？

尝试 1: 分母用 |P|
```
Score = Σ METEOR / |P|
问题: 一个 g 被多次匹配，分子可能 > 分母
```

尝试 2: 分母用 |G|
```
Score = Σ METEOR / |G|
问题: 一个 g 被多次匹配，分子可能 > 分母
```

> 💡 需要**一对一匹配**才能保证分数 ≤ 1.0 → SODA 的动机
